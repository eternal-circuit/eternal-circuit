# Frontier intelligence and source verification

Goal: sample the present science/technology frontier without conflating hype, prototype, possibility, feasibility or probability.

## Sources and order of trust

- **Primary evidence:** peer-reviewed publications, preprints **clearly labeled unreviewed**, datasets, supplementary methods, benchmarks, original technical documentation, code repositories and released experimental artifacts.
- **Independent verification:** replications, critical technical analyses, robust measurements from separate labs or groups, and corrections/retractions.
- **Early signals:** X posts and threads, lab accounts, engineer build logs, conference talks, demos, startup announcements, and GitHub project updates. Useful **for discovery, not proof**.
- **Context:** reputable science reporting and surveys that point back to inspectable original sources.

## X scout workflow

Find emerging work via researchers, builders, labs, open-source maintainers and technical communities. For each lead, record original URL, author/affiliation, posting date, concrete asserted capability, whether a working demo/data/code is linked, and any commercial conflicts. Seek primary artifacts and skeptical independent responses. Beware edited videos, fake accounts, performance theater, benchmark leakage, self-reported numbers and cherry-picked successes.

Use X search where access permits; if access is unavailable, record a coverage gap rather than pretending the platform was monitored. Do not scrape behind authentication or fabricate posts. Follow links into technical evidence before any scientific gate decision.

## Coverage themes

AI agents and autonomy; inference/training compute and energy; robotics; semiconductors; distributed systems; security; brain-computer interfaces; memory and cognition; human-computer interaction; spaceflight, propulsion and life support; ecology and climate; statistics and complex systems. Scope each search by the actual story mechanism.

## Cadence

For active, fast-moving story premises: recheck key claims before each major revision and release. A weekly research digest could help if explicitly scheduled and configured; this file alone does not create a monitoring job. Maintain a dated evidence ledger and avoid unsupported claims that monitoring is continuous.
